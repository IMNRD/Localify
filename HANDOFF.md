## 1. Exec summary

**Localify** is an offline Windows 10 desktop music player that looks and navigates like Spotify but plays only the user's own local audio files (mp3, flac, m4a, aac, wav, ogg, opus). It indexes user-chosen folders, shows Home / Search / Songs / Liked Songs / Album / Artist / Queue / Settings views, plays with queue + shuffle + repeat, and lets the user create playlists with custom cover images (or an auto 2×2 art mosaic). After adding a folder it offers to turn each music subfolder into a playlist. `[discussion]` Built for one non-expert Windows user; no accounts, no network, no Spotify branding.

**Stack:** Electron (declared `^39.8.10`) main process in CommonJS, vanilla HTML/CSS/JS renderer (classic `<script>` tags, no bundler/framework), one runtime dependency `music-metadata` (ESM, loaded via dynamic `import()`), JSON-file persistence. `[code]` (`package.json`)

**Entry points:** `src/main/main.js` (`package.json` `main`) → loads `src/renderer/index.html` → scripts `core.js`, `player.js`, `app.js` in that order.

**Fastest path to running** (Windows or Linux with a display):
```
npm install
npm start
```
Windows users normally double-click `startup\1 - Install Localify.bat` then `Start Localify.bat` (see §4). `[discussion]` The owner runs it from `F:\AI-Projects\localify`.

## 3. Technical overview

### 3.1 Main process

**`main.js`** `[code]`
- Registers privileged scheme `localify` (standard, secure, supportFetchAPI, stream) via `protocol.registerSchemesAsPrivileged` — must run before `app` is ready.
- Disables Chromium media-key handling (`disable-features=HardwareMediaKeyHandling,MediaSessionService`) and registers `globalShortcut` for `MediaPlayPause/MediaNextTrack/MediaPreviousTrack`, forwarded to the renderer as `media-key` events (`playpause|next|prev`). `[discussion]` Done so a key press can't fire twice.
- `BrowserWindow` hardening: `contextIsolation:true`, `nodeIntegration:false`, `sandbox:true`; `will-navigate` prevented; `setWindowOpenHandler` denies.
- `app.setAppUserModelId('local.localify.app')` on win32 so the taskbar groups/pins as Localify. `[discussion]` Added after the owner found `npm start` pins "Electron".
- `LOCALIFY_USERDATA` env var overrides `userData` (test hook used by `test/smoke.js`).
- Menu is removed (`Menu.setApplicationMenu(null)`); scan starts on `did-finish-load`.

**`store.js`** `[code]` — `createStore(dir)` loads `library.json` from `app.getPath('userData')` (Windows: `%APPDATA%\Localify`, because `productName` is set). State shape:
`{folders:[abs paths], tracks:{id:Track}, playlists:[Playlist], liked:[trackId], recent:[trackId≤50], lastScanAt}`. `save()` is debounced 400 ms and writes `library.json.tmp` then renames (atomic); `flush()` runs on `will-quit`. A corrupt file is renamed `library.corrupt-<ts>.json` and the app starts empty (`store.recovered` → renderer toast). `snapshot()` returns state with `tracks` as an array; `lite()` returns `{playlists, liked, recent}`.

Track: `{id, path, title, artist, albumArtist, album, trackNo, discNo, year, durationSec, artHash|null, addedAt, mtimeMs, size, available, plays}`.
Playlist: `{id /^p[a-f0-9]{12}$/, name, description≤300, image|null (filename), trackIds[], createdAt, updatedAt, sourceKey?}`.

**`scanner.js`** `[code]` — `scan(store, artDir, onProgress, onChunk)`: walks `store.state.folders` for extensions in `EXTS`; dedupes by track id (`sha1(lowercase path).slice(0,16)`); 4 concurrent workers; skips files whose `mtimeMs` and `size` match; otherwise `readTags` (fallbacks: title = filename, "Unknown Artist", "Unknown Album"; any parse error is logged and fallbacks kept). Cover art is hashed (sha1 of bytes) and written once to `userData/art/<hash>.<jpg|png>`. Files not seen get `available:false` (never deleted). Existing `addedAt` and `plays` survive re-reads. `onChunk` fires every 1000 files so the UI can refresh mid-scan. `[discussion]` Missing files are kept so playlists keep their slots.

**`folders.js`** `[code]` — `computeGroups(state, onlyRoot)` groups *available* tracks by their immediate parent directory when that directory is not itself a registered root; skips groups whose key (`sha1(lowercase dir).slice(0,12)`) already appears as some playlist's `sourceKey`; names = folder basename, duplicates become `Parent - Name` (≤100 chars); tracks ordered by disc, track number, then natural filename compare.

**`ipc.js`** `[code]` — see §8 for the API table. Notable internals:
- `runScan()` serializes scans (`scanning`/`again` flags) and sends `scan-progress` `{scanning,done,total}` then a full `state` snapshot when finished.
- `toSquareJpeg(file)`: opens a throw-away hidden sandboxed `BrowserWindow` on the file URL, draws the centre square to a 640×640 canvas, returns JPEG q0.88 bytes, validates 640×640 with `nativeImage`, 15 s watchdog. `[discussion]` Chosen because `nativeImage` cannot decode WebP/GIF (verified empirically in the smoke test).
- Mutations return `store.lite()`; the renderer must merge it (`L.mergeLite`).

**`protocols.js`** `[code]` — `localify://media/<16-hex id>` (only available tracks; full HTTP Range support → 200/206/416, MIME by extension), `localify://art/<40-hex sha1>` (tries `.jpg` then `.png` in `userData/art`), `localify://pl/<file>` (must match `^[\w.-]+\.jpg$`, resolved inside `userData/playlist-images`). Anything else → 404.

### 3.2 Renderer

**`core.js`** `[code]` — builds `window.L`: `$ $$ esc norm fmt fmtLong hash icon`, state `L.S` (tracks Map, list, sorted, albums/artists Maps + sorted lists, playlists, liked Set + `likedOrder`, recent, folders, lastScanAt, scan), `L.setTracks(arr)` (derives albums keyed by `norm(albumArtist||artist)+"\u0001"+norm(album)`, artists keyed by `norm(track.artist)`, search haystack `t._h`, `t._album`, `t._artist`), `L.mergeLite`, `L.toast`, cover builders `L.art / L.likedCover / L.plCover` (playlist cover = custom image, else 1 art, else 2×2 mosaic of first four distinct arts, else placeholder). Icons are inline SVG path strings in the `P` map.

**`player.js`** `[code]` — `L.P` holds `queue` (ids), `order` (permutation of queue indices), `pos` (index into `order`), `shuffle`, `repeat` (`off|all|one`). API: `play(ids,start) toggle next(manual) prev jump(orderPos) setShuffle cycleRepeat enqueue(ids,next) removeUpcoming(orderPos) cur() track()`, plus `L.initBar`, `L.renderBar`, `L.restoreLast`. Unavailable tracks are skipped by `seek()`. A play is counted (IPC `recordPlay`) once per load at ≥30 s or on `ended`. Audio `error` → toast "Skipped: file not found" and next (bounded by `P.errs`). Persists volume/shuffle/repeat/last track in `localStorage` keys `lf.vol|shuffle|repeat|last`. Dispatches `player-change` on `window` for repaint.

**`app.js`** `[code]` — one IIFE. `navigate(route)` keeps a history array; `VIEWS` = `home search songs liked playlist album artist queue settings` (each returns an HTML string); `renderView(keepScroll)` swaps `#view`, then mounts virtualized lists (`mountList`, fixed `RH = 56` px rows, windowing against `#main` scroll). `table(ids, opts)` registers a list to mount; `rowHTML` builds a row. Click handling is a single delegated `document` listener keyed on `data-play`, `.rowplay`, `data-like`, `data-more`, `data-act` (map `actions_`), `data-go`. Context menu = `openTrackMenu`/`playlistPicker`; dialogs = `showModal` (`editPlaylist`, `confirmDelete`, `offerGroups`). Boot IIFE at the bottom: `L.initBar()`, `api.getState()`, `applyState`, `L.restoreLast()`, subscribes to `api.onState/onScanProgress/onMediaKey`.

### 3.3 Why things are the way they are

- **Electron over a local web app / Tauri** `[discussion]` — the owner never chose; Claude recommended Electron (double-click app, media keys, native folder picker, no localhost server). The owner went with it.
- **One spec, no sub-specs** `[discussion]` — components share one stack/builder. The original spec file was later removed from the repo at the owner's request (cleanup); its last version is in git history (`git show 0e0fa6e:Localify_SPEC.md`). This document and `GETTING_STARTED.md` are now the requirements record. `[code]` (git history)
- **JSON store, no SQLite** `[inferred]` — avoids native modules needing a Windows compiler; fine at tens of thousands of tracks but the whole file is rewritten on each save.
- **Custom `localify://` protocol instead of `file://`** `[discussion]` — renderer can only reach indexed ids/hashes, never arbitrary paths.
- **"Songs" nav item, Settings button for subfolder playlists, edit-dialog cover changes apply immediately** `[discussion]` — deliberate small additions/deviations from "pure Spotify".
- **No Spotify name/logo; logo is a green minimalist smiley** `[discussion]` (`assets/logo.svg`, same SVG copied to `src/renderer/logo.svg` and rendered to `assets/icon.png` / `assets/icon.ico`).
- **Real `Localify.exe` build** `[discussion]` — `npm start` pins `electron.exe`; `npm run pack` (`electron-builder --win dir`) produces `dist/win-unpacked/Localify.exe` with icon and product name embedded.

## 5. End-to-end walkthrough

**A. Add a music folder → library → subfolder-playlist prompt**
1. Settings view (or the Home CTA) button `data-act="addfolder"` → `actions_.addfolder` in `app.js` → `api.addFolder()`.
2. `preload.js` → `ipcMain.handle('addFolder')` in `ipc.js`: `dialog.showOpenDialog` (folder), pushes the path into `store.state.folders`, `store.save()`, calls `runScan()`, returns `{folders, added}`.
3. Renderer stores `pendingGroups = r.added`.
4. `runScan()` → `scanner.scan()`: `walk` → per file `readTags` (`music-metadata`) → writes `userData/art/<hash>.jpg` → fills `store.state.tracks` → progress events (`scan-progress`) and every 1000 files a `state` snapshot.
5. On finish `ipc.js` sends `scan-progress {scanning:false}` then `state`. Renderer `onScanProgress` sees the transition and calls `offerGroups(root)` → `api.getFolderGroups(root)` → `folders.computeGroups`.
6. If groups exist, `showModal` lists them; **Create playlists** → `api.createPlaylistsFromFolders(keys)` → main recomputes groups, pushes playlists with `sourceKey`, returns `{created, ...lite}` → `merge()` re-renders sidebar and view.
7. `onState` → `applyState` → `L.setTracks` rebuilds albums/artists → `renderView(true)`.

**B. Play a song**
1. Double-click a row (`document` `dblclick` handler in `app.js`) → `P.play(host._ids, i)` → `load()` → `setCurrent(true)` sets `audio.src = localify://media/<id>`.
2. Chromium requests it → `protocols.handle` → `serveFile` streams with `Range` support.
3. `timeupdate` updates the seek bar; at ≥30 s `count()` → `api.recordPlay(id)` → `ipc.js` increments `plays`, updates `recent`, `store.save()`.
4. `ended` → `P.next(false)` (repeat-one restarts; end of queue with repeat off → `endOfQueue()` pauses and resets to first track).

## 6. Conventions & invariants — what not to break

- **Renderer escapes everything.** Every interpolated string in HTML templates goes through `esc()` (including `data-*` attribute values). A smoke test asserts a track titled `<img src=x onerror=alert(1)>` renders as text. `[code]`
- **No raw paths over IPC.** Handlers accept ids/hashes/validated values; the only string paths from the renderer are `removeFolder(folder)` (filtered against registered folders) and `getFolderGroups(root)` (must match a registered folder, else throws). Track objects sent to the renderer do include `path` but the renderer never sends it back. `[code]`
- **Id formats:** track `^[a-f0-9]{16}$`, art hash `^[a-f0-9]{40}$`, playlist `^p[a-f0-9]{12}$`, folder-group key 12 hex. Protocol and IPC validation depend on them.
- **Mutations return `store.lite()`** and the renderer must merge it (`merge(lite)` in `app.js` → `L.mergeLite` + re-render) — adding state to `lite()` requires updating `mergeLite`.
- **Path comparison on Windows:** use lowercase `path.resolve` (`norm` helpers in `ipc.js`/`folders.js`); track ids hash the lowercased path.
- **Never delete tracks on rescan** — mark `available:false`. Only `removeFolder` deletes tracks.
- **Row height 56 px is duplicated** in `app.js` (`RH`) and `styles.css` (`.row{height:56px}`); virtualization breaks if they diverge. Grid templates for rows/header exist twice (with and without Album column).
- **Renderer is classic scripts on `file://` with a strict CSP** (`default-src 'self'; img-src 'self' localify: data:; media-src localify:; style-src 'self' 'unsafe-inline'`): no ES modules, no inline `<script>`, no remote assets, no `fetch` to `localify:` from the page. `[code]` (`index.html`)
- **Main process is CommonJS;** `music-metadata` must stay a dynamic `import()` (see `loadMm` in `scanner.js`).
- **Design tokens** live in `:root` of `styles.css` (colours, radius); the accent is `#34e07a` and the logo is `assets/logo.svg` (a copy lives in `src/renderer/logo.svg`; keep them identical).
- **`.bat` files must stay ASCII + CRLF** (`.gitattributes`: `*.bat text eol=crlf`) and avoid parentheses inside `if (...)` block echo text. `[inferred]` (cmd.exe parsing)
- **Working style requested by the owner** `[discussion]`: state assumptions, prefer the minimum code, make surgical changes, define verifiable success criteria and test them; don't add unrequested features. Commits in this repo end with the `Co-Authored-By: Claude …` and `Claude-Session:` trailers.
- **Docs:** update `GETTING_STARTED.md` (user-facing) and this file when behaviour or commands change. The owner removed the spec file; don't recreate it unless asked.

## 7. Gotchas / landmines / tech debt

- **Windows is untested.** Everything was verified on Linux (headless Electron). Expect to debug `.bat` scripts, media keys, and `electron-builder` on Windows first. `[discussion]`
- **`pendingGroups` can fire early:** if a scan is already running when the user adds a folder, `runScan` queues a second scan (`again`), and the first scan's completion triggers the subfolder prompt before the new folder is indexed. `[inferred]` from `ipc.js` `runScan` + `app.js` scan-progress handler.
- **Image extension is not enforced in main.** `setPlaylistImage` filters by the dialog's extension list only; `ipc.js` checks size (≤20 MB) but not the extension of `r.filePaths[0]`, and `toSquareJpeg` loads that file URL in a hidden window (sandboxed, no preload, but JS-enabled). A non-image fails, but an HTML file would load. Consider an allowlist check. `[code]`
- **`playCtx` has an unused destructure** (`const [kind, id] = ctx.split(':')` at the top of the function after the `ids` lookup) and relies on an ad-hoc `P.ctx` property that is not declared in `player.js`. `[code]`
- **Album page artist link** finds an artist by *name equality* with `album.artist` (`albumArtist||artist`); if the album artist isn't a track artist the link is empty and click is ignored (`data-go` ending in `:` is guarded). `[code]`
- **Whole-library JSON rewrite + full `state` snapshot** to the renderer after scans: fine at 20k tracks in the smoke test (view render ~0.7 s), untested beyond that. A hard kill can lose up to 400 ms of changes. `[code]` `[inferred]`
- **Sidebar library list is capped at 300 rows** with a "use the filter" note. `[code]` (`renderSide`)
- **Dialog cover changes apply immediately** even if the user presses Cancel (only name/description are discarded). Intentional. `[discussion]`
- **Moving a music file changes its id** (hash of path): playlist entries for the old path become "Unavailable track"; there is no re-link/relocate feature.
- **`Start Localify.bat` leaves a minimized console** in the taskbar; the built `Localify.exe` doesn't. `[discussion]`
- **`dist/` is ~330 MB and must stay beside its files;** `.gitignore` excludes it. A copy of only `Localify.exe` won't run.
- **smoke.js monkey-patches `dialog.showOpenDialog`** (via a `nextDialog` variable) to drive native dialogs; any renamed/relocated dialog call in `ipc.js` breaks it. Smoke test also depends on exact DOM selectors (`[data-act=…]`, `#modal`, `.row`, `#liblist`). `[code]`
- No TODO/FIXME/HACK comments exist in the repo (grep returned none). `[code]`

## 8. Integration & extension guide

**IPC API** (`ipc.js` handlers ↔ `preload.js` `window.api`; all validate arguments): `[code]`

| Method | Args | Returns | Notes |
|---|---|---|---|
| `getState` | — | snapshot + `recovered` | tracks as array |
| `addFolder` | — | `{canceled}` or `{folders, added}` | opens folder dialog, starts scan |
| `removeFolder` | folder string | `{folders}` | deletes tracks no longer under any folder; pushes `state` |
| `rescan` | — | `true` | |
| `getFolderGroups` | `root|null` | `[{key,name,rel,count}]` | root must be registered |
| `createPlaylistsFromFolders` | `keys[]` | `{created, playlists, liked, recent}` | keys must match computed groups |
| `createPlaylist` | optional name | `{id, ...lite}` | default `My Playlist #N` |
| `updatePlaylist` | id, `{name,description}` | lite | |
| `deletePlaylist` | id | lite | deletes cover file |
| `addToPlaylist` | id, trackIds[≤5000] | lite | unknown ids ignored |
| `removeFromPlaylist` / `reorderPlaylist` | id, index / id, from, to | lite | bad index throws |
| `setPlaylistImage` / `clearPlaylistImage` | id | `{canceled,…lite}` / lite | image dialog in main; throws "Could not read that image" |
| `toggleLike` | trackId | lite | most-recent first |
| `recordPlay` | trackId | `{trackId, plays, recent}` or null | |
| events | `onState(snapshot)`, `onScanProgress({scanning,done,total})`, `onMediaKey('playpause'|'next'|'prev')` | | |

**Recipes**
- **Add an IPC method:** `h('name', fn)` in `ipc.js` (validate every arg; mutate `store.state`; `store.save()`; return `store.lite()` or a small object) → expose in `preload.js` → call from `app.js` and `merge()` the result → add a check in `test/smoke.js`.
- **Add a view:** add a function to `VIEWS` in `app.js`; navigate with `go('name:id')` / `navigate({view,id})`; add nav highlighting in `syncChrome` if it has a nav button; add markup to `index.html` only for permanent chrome.
- **Add a file format:** extend `EXTS` in `scanner.js` and the `MIME` map in `protocols.js`; confirm Chromium can decode it.
- **Add a track column:** `rowHTML` + the `.thead` markup in `table()` in `app.js`, plus both grid templates in `styles.css` (`.thead,.row` and the `.no-album` variants).
- **Add a context-menu item:** `openTrackMenu` in `app.js` (items are `{label, fn | sub, danger?}`).
- **Add a tag field:** `readTags` (`scanner.js`) → Track shape in `store.js`/`core.js` → use it in `core.js` `setTracks` or views. Old libraries need a rescan; changing `mtimeMs/size` skipping may require forcing re-read.
- **Add an icon:** add a path string to `P` in `core.js`, use `icon('name', size)`.
- **Add a keyboard shortcut:** `keydown` listener in `app.js` (guard against typing in inputs like the Space handler).
- **Change the theme:** edit `:root` tokens in `styles.css`; keep `assets/logo.svg`, `src/renderer/logo.svg`, `assets/icon.png` and `assets/icon.ico` consistent if the logo colours change.
- **Releases:** build with `npm run pack`, or add a signed installer target in `package.json` `build`.

## 10. Sensitive areas — handle with care

No auth, payments, accounts or secrets exist. `[code]` Treat these with care:
- **`protocols.js`** — serves files from disk to the renderer; keep id/hash/filename validation (`⚠️` path traversal tests in `test/smoke.js` cover `..`, absolute paths, `library.json`).
- **`main.js` / `index.html` hardening** — `contextIsolation`, `sandbox`, no node integration, CSP, navigation/popup blocks. Don't loosen.
- **`ipc.js` argument validation** — the renderer is a trust boundary; every new handler must validate.
- **`toSquareJpeg`** — loads a user-chosen file URL in a hidden window (see §7 extension note).
- **Destructive scripts** — `Uninstall Localify.bat` runs `rmdir /s /q` on `node_modules`, `dist`, and (only after a Y/N prompt) `%APPDATA%\Localify`; `Install`/`Build` write Desktop and Start-menu shortcuts via PowerShell `-ExecutionPolicy Bypass` (process-scoped).
- **Personal data** — listening history (plays, recent, liked) and library index live only in `userData`; no network use. Nothing hard-coded secret found.
